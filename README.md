# Completion Rate Agent

Невеликий проєкт для ДЗ 2: **база даних → агент → аналіз → дашборд**.
Дашборд у Streamlit показує completion rate навчальної платформи, а під ним можна поставити агенту запитання природною мовою й отримати відповідь із цифрами з бази.

## Що робить проєкт

- Показує 3 метрики: кількість записів на курси, completion rate, кількість унікальних студентів.
- Показує воронку записів однією смугою, графік completion rate за рівнем курсу (з лінією середнього) і рейтинг топ-10 курсів зі шкалами.
- Має поле для запитання. Агент (Gemini) обирає один із готових SQL-інструментів, отримує цифри з бази й пояснює їх українською.
- Якщо Gemini недоступний (ліміти, «high demand», немає ключа), агент не падає, а відповідає за шаблоном із тих самих цифр.

## Які дані

Навчальна база `coursera_capstone` (PostgreSQL, лише читання). Використовуються таблиці `enrollments` і `dim_course`.
Це навчальні дані, у проєкті немає робочих даних компанії. Дані в базі проєкт не змінює: усі запити тільки `SELECT` у транзакції `READ ONLY`.

### Визначення метрик

Визначення задані в одному місці, у файлі `semantic_layer.yaml`.

- **Completed** = `funnel_state = 'certified'` (студент отримав сертифікат).
- **Completion rate** = завершені записи / усі записи × 100.
- Рахуємо **записи на курс** (enrollment), а не студентів.
- У рейтингах показуємо курси й групи, у яких не менше 30 записів (робоче припущення, щоб «1 з 1 = 100%» не потрапляло в топ).

Чому саме це визначення: у базі є ще `completed_at IS NOT NULL` (4 911 записів) і `progress_pct = 100` (4 541 запис). За `certified` усі три ознаки збігаються (4 555 записів), тому це найстрогіший варіант. Інше визначення задається зміною `sql_condition` у `semantic_layer.yaml`.

### Відомі проблеми даних

- `progress_pct` має значення до 104 (понад 100%), це поле в метриках не використовується.
- `enrolled_at` має формат `ДД.ММ.РРРР`, `completed_at` має формат `РРРР-ММ-ДД`, обидва типу `text`; дати в метриках не використовуються.
- 356 записів мають `completed_at`, але не сертифіковані.

## Як запустити

1. Встановити Python 3.10+ і відкрити папку проєкту в терміналі.
2. Створити й активувати віртуальне середовище.
   - Mac/Linux: `python3 -m venv .venv && source .venv/bin/activate`
   - Windows: `python -m venv .venv` і `.venv\Scripts\activate`
3. Встановити залежності: `pip install -r requirements.txt`
4. Скопіювати `.env.example` у `.env` і заповнити:
   - `DATABASE_URL` — рядок підключення до бази (його дає викладач);
   - `GEMINI_API_KEY` — ключ із Google AI Studio;
   - `GEMINI_MODEL` — назва моделі (актуальні назви: https://ai.google.dev/gemini-api/docs/models);
   - `LLM_MODE=on` або `off` (`off` вимикає Gemini: агент відповідає лише за шаблоном).
5. Запустити: `streamlit run app.py`. Відкриється сторінка в браузері.

Файл `.env` у git не потрапляє (`.gitignore`), у репозиторій потрібно додавати лише `.env.example`.

## Структура

| Файл | Призначення |
|---|---|
| `app.py` | Дашборд Streamlit: метрики, графік, таблиця, поле запитання |
| `agent.py` | Агент: Gemini обирає інструмент і пояснює результат; режим без LLM |
| `tools.py` | 4 інструменти з фіксованим SQL (read-only) |
| `semantic_layer.yaml` | Бізнес-визначення метрик, виміри, поріг рейтингів |
| `probe_schema.py`, `probe_values.py` | Розвідка схеми й розподілів (лише агрегати) |
| `check_gemini.py` | Діагностика ключа й моделі Gemini окремо від дашборда |
| `.streamlit/config.toml` | Тема Streamlit (світла, фіксовані кольори) і вимкнена телеметрія |
| `tests/` | Тести на тестовій копії схеми в SQLite (реальна база не потрібна) |
| `requirements.txt`, `.env.example`, `.gitignore` | Залежності й налаштування |

## Як влаштований агент

Агент один і простий: Gemini + 4 Python-інструменти (`get_overview`, `get_funnel`, `get_completion_by_course`, `get_completion_by_dimension`).
Модель **не пише SQL**: вона лише вибирає інструмент і параметри, цифри рахує код. Тому відповідь можна перевірити за таблицею під нею («Дані, на яких побудовано відповідь»).
До Gemini потрапляють лише агрегати (назви курсів, кількості, відсотки), без `user_id` і без рядків даних.

## Тести

```
pip install pytest
pytest
```

Тести перевіряють цифри інструментів проти незалежного підрахунку на тестових даних, відхилення небезпечних запитів, режим без LLM та запасний режим, коли Gemini недоступний.

## Обмеження

- Агент відповідає лише на питання, які покривають 4 інструменти. На інші питання він має чесно сказати, що не може відповісти.
- Дати не використовуються (через різні текстові формати), тому динаміки за часом немає.
- Безкоштовний тариф Gemini має ліміти й може відповідати «high demand»; у такому разі працює режим без LLM.
- Для безкоштовних ключів Google може використовувати вміст запитів для покращення продуктів. Цей проєкт працює з навчальними даними; для робочих даних використовуйте `LLM_MODE=off` або погоджені політикою компанії налаштування.
